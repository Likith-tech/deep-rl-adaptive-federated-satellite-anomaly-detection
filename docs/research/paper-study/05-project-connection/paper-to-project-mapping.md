# Paper → Project Phase Mapping

**Note on phase numbering:** this maps literature to the project's **actual, current** phase structure (verified against `docs/project-progress/00-project-plan.md` and the Phase 9A/9B write-ups), which has progressed further than a simple "Phase 1 → Phase 5, then later adaptive FL/DRL" framing — rule-based adaptive FL and a fully-executed DQN experiment already exist as of this analysis. See `03-comparison/research-evolution.md` and `04-research-gap/our-project-positioning.md` for the full reconciliation.

| Phase | Which papers support it | Concept learned | Why the design choice is reasonable | What differs from the paper(s) |
|---|---|---|---|---|
| **Phase 1** — Dataset & pipeline (NSL-KDD) | General FL-IDS literature convention (ACM CSUR FL-IDS survey) of validating new mechanisms on established intrusion datasets | Use a well-understood benchmark to isolate whether the *mechanism* (not the data) works | NSL-KDD is thoroughly studied, letting later phases' FL/DRL results be interpreted without also debugging an unfamiliar dataset | FedSTAR uses STIN/TON_IoT/Bot-IoT instead — no paper in our set uses NSL-KDD |
| **Phase 2** — Baseline anomaly detection (MLP) | Standard supervised-classification framing shared by FedSTAR/FLOGA-AD | Establish a non-federated, non-adaptive floor before adding complexity | Needed as the reference point every later phase (5, 6, 7, 8, 9B) is compared against | Simpler than any classifier in the 4 papers (all use LSTM-family or spatio-temporal backbones) |
| **Phase 3** — Temporal model (GRU+Attention) | Yang et al. 2021 (attention-over-LSTM); conceptually parallel to FedSTAR's LKA (different attention mechanism, same motivation) | Attention improves use of long-range/structural information over a plain recurrent unit's own memory | Independently confirmed useful by two papers in two different domains (telemetry vs. network traffic) | Our GRU+attention combination is our own implementation choice, not copied from either paper's exact architecture |
| **Phase 4** — Simulated satellite client environment | FedSTAR's (and FLOGA-AD's) Dirichlet-based client simulation from centralized data | Dirichlet partitioning as the standard way to simulate Non-IID clients when real multi-satellite data doesn't exist | No public, real, multi-satellite federated dataset exists (a field-wide gap) — simulation, with measured (not assumed) severity, is the only currently available option | Ours adds simulated *resource* conditions (bandwidth/latency/compute/availability/connectivity) alongside label-skew — FedSTAR's Non-IID simulation is label-skew only |
| **Phase 5** — Local training (independent, no FL) | Standard FL-literature practice (implicit in how FedSTAR frames FedAvg as its own starting baseline) | Need to know whether FL is adding value over independent local training at all | Answers "is combining clients even worth it here" before adding cost/complexity | — |
| **Phase 6** — Federated learning (FedAvg) | McMahan et al. 2017 (FedAvg — cited directly in FedSTAR's own reference [11]) | The universal FL starting point | Every adaptive method in the literature (FedSTAR, FLOGA-AD, ours) is compared against plain FedAvg first | Unmodified, standard baseline — no deviation |
| **Phase 7** — Non-IID FL experiments (Dirichlet α-sweep) | FedSTAR's Dirichlet Non-IID framing, extended into a controlled multi-value sweep | Isolate heterogeneity as a single experimental variable, measured via Jensen-Shannon distance | Stronger evidence than a single fixed η (FedSTAR reports only η=0.5) | Our own finding — KDDTest+ F1 is **non-monotonic** in α — is not reported by any of the 4 papers |
| **Phase 8** — Rule-based adaptive FL | FedSTAR's/RAFL's general "not all clients deserve equal trust" framing, implemented as a fixed, transparent formula (not learned, unlike either paper) | Establish whether *any* adaptive weighting helps before paying the cost of a learned (DRL) controller | Directly tests the simplest possible adaptive mechanism first | Our own finding — no single fixed rule wins on both F1 and fairness simultaneously — is the direct empirical motivation for attempting Phase 9B |
| **Phase 9A** — Real spacecraft telemetry validation (OPSSAT-AD) | Hundman/Yang/Maleki Sadr's shared standard of validating against real spacecraft data | Reuses the Phase 3 architecture on real, independently-verified ESA telemetry | Answers "has anything in this project been tested on real spacecraft data" — a distinguishing point vs. FedSTAR/FLOGA-AD, which use no real satellite data at all | Current run uses `sequence_length=1` — disclosed honestly as not yet exercising genuine temporal modeling |
| **Phase 9B** — DQN-driven adaptive FL | FedSTAR's "DRL controls the aggregation/clustering process" pattern, implemented with DQN instead of SAC and a fixed discrete catalogue instead of clustering+continuous knobs | DQN (replay buffer, target network, epsilon-greedy — Mnih et al. 2015's building blocks) applied to a small, fully-named, discrete action set | Matches this project's deliberately smaller, fully-explainable, capstone-appropriate scope | The controlled three-way (fixed/rule/learned) comparison and the honestly-reported negative result (DQN did not beat Phase 8's best rule) with a specific, falsifiable explanation (training-partition diversity) — neither FedSTAR nor FLOGA-AD report an equivalent staged comparison for their own controllers |

## What differs from the papers, summarized across every phase

1. **No paper in our set uses NSL-KDD or a comparably terrestrial dataset as a satellite-client stand-in** — this is our project's own choice, with its own honestly-disclosed limitation (it is not satellite-specific traffic).
2. **No paper reports a controlled fixed→rule→learned staged comparison on the identical pipeline** — this is the single most distinctive methodological feature of our own Phase 6→8→9B progression.
3. **No paper (including ours) has merged a federated/DRL track with a real-spacecraft-telemetry track** — Phase 9A and Phase 9B remain separate in our project, exactly as FedSTAR's own use of no real satellite data remains a separate, disclosed limitation on its side.
